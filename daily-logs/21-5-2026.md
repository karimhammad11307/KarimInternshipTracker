## Part 1: Core Concepts & Project Architecture (Chapter 9)

### 1. Code Organization & Compilation Units
*   **Modules:** The foundational building block used to split programs into logical, manageable pieces. Modules draw clean boundaries around scope, privacy, and responsibilities.
*   **Writing a Program vs. Library:** 
    *   *Programs (Binaries):* Produce an executable file starting from a `main.fn` entry point.
    *   *Libraries:* Contain reusable logic designed to be consumed by other projects, lacking a `main` entry point.
*   **Referencing Other Modules and Crates:** Exploring how to pull functionality from other files or external packages (crates) using paths and the `use` keyword.
*   **Referencing Multiple Items:** Utilizing nested paths and brackets (e.g., `use std::collections::{};`) to cleanly import multiple dependencies in a single line without cluttering code headers.

### 2. Module Hierarchies & Visibility Control
*   **Creating Modules & Module Hierarchy:** Breaking code structures down into parent-child relationships using directories and files to map out a clear, navigable backend architecture.
*   **Inline vs. Separate File Modules:** 
    *   *Inline:* Declaring a module directly within an existing file using the `mod name { ... }` block syntax.
    *   *Separate File:* Moving code to an independent file/folder system for cleaner project maintenance.
*   **Internal Module Referencing:** Navigating module trees using absolute paths starting from the root (`crate::`) or relative paths using keywords like `self` and `super`.
*   **Exporting & Structure Visibility:** 
    *   The `pub` keyword makes modules, functions, and structs accessible across structural boundaries.
    *   *Crucial Detail:* Making a `struct` public does not automatically make its fields public. Every field must be individually marked with `pub` to grant outside access, preventing state corruption.

### 3. Core Presets & Custom Adaptations
*   **Prelude:** The standard collection of traits and types that Rust automatically imports into *every single file* for you behind the scenes (like `Option`, `Result`, and `Clone`).
*   **Your Own Prelude:** A powerful production pattern where a custom library exports its own `prelude` module, allowing consumers to write `use my_library::prelude::*;` to instantly access all the essential traits and types required for work.
